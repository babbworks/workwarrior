# Journal / JRNL Service — Excellence Audit

Date: 2026-07-13
Method: static read of every jrnl-touching path + executed proofs (reproductions below)
Status: **findings only — no production code changed.** Cards to follow (Gate A).

## 1. Summary

The journal service has **no service directory**. Unlike every other capability in Workwarrior,
`journal` is not `services/journal/` — it is implementation code living inside `bin/ww`, plus a
config wizard in `services/custom/`, plus a Python parser in `lib/`, plus three byte-identical
template scripts scattered across `services/`.

The dedicated test suites are green (88/88). Every defect below is in code those suites do not reach.

| Severity | Finding | Location |
|---|---|---|
| **CRITICAL** | Shell→Python code injection via `--journal` | `bin/ww:3592`, `bin/ww:3672` |
| **HIGH** | Silent fallback writes entries to the wrong file | `bin/ww:3603` |
| **HIGH** | Silent fallback silently drops annotations | `services/browser/server.py:2003` |
| **MEDIUM** | jrnl entry grammar re-implemented in 4+ files, no contract | see §5 |
| **MEDIUM** | Three byte-identical copies of one script | see §6 |
| **LOW** | 4 scripts violate the mandated shebang standard | see §6 |

## 2. CRITICAL — code injection in `ww journal write --journal`

`bin/ww:3586` opens an **unquoted** heredoc (`<<PYEOF`), so the shell expands variables *into the
Python source text* before Python ever sees it:

```bash
target_file="$(python3 - <<PYEOF
...
journal_name = "${ww_journal}"        # <-- user-controlled, interpolated into source
```

`ww_journal` comes straight from `--journal` (`bin/ww:3575-3576`) with **no validation, quoting, or
escaping anywhere between the CLI and the interpreter**. A `"` in the value terminates the Python
string literal and everything after it is executed.

### Reproduction (executed 2026-07-13, faithful copy of the heredoc)

```
$ resolve 'x"; print("INJECTED: arbitrary python ran as the user"); #'
INJECTED: arbitrary python ran as the user
journals/default.txt
```

The same pattern repeats at `bin/ww:3672` (`journal_key = "${resolved_journal}"`) in the
`ww journal task` path.

**Why it matters beyond the obvious.** Journal names are not always hand-typed — they arrive from
`ww.yaml` defaults, from the browser UI, and from the questions-service templates. Any path that can
seed a journal name can execute Python as the user.

**Fix direction:** stop interpolating. Pass values as `argv` (`python3 - "$ww_journal" <<'PYEOF'`,
quoted heredoc, read via `sys.argv[1]`). The quoted heredoc is the load-bearing part — it disables
shell expansion into the source entirely. This is a one-line-per-site change and it closes the whole
class, not just this instance.

## 3. HIGH — silent fallback writes to the wrong journal file

`bin/ww:3601-3603`:

```python
except Exception:
    print(os.path.join(base, "journals", "default.txt"))
```

A malformed `jrnl.yaml`, an unreadable file, or a missing PyYAML **is not an error**. The resolver
prints `journals/default.txt` and `ww journal write` cheerfully appends the user's entry there.

The user asked for `--journal work`, got no warning, and their entry is now in a different file.
For a journal — an append-only record whose entire value is that it is trustworthy — writing to the
wrong file without saying so is a data-integrity bug, not an ergonomics one.

**Fix direction:** distinguish the three cases. Journal-not-found → exit 1 with a message listing
valid journals. Config unreadable/malformed → exit 2 (system error, per the exit-code contract).
Only "no `--journal` given" may fall back to default, and that is not an exception path.

## 4. HIGH — the browser silently drops annotations

`services/browser/server.py:1999-2004`:

```python
try:
    entries = scanner.parse_file(journal_file)
    ...
except Exception:
    pass
# Fallback: plain parse without annotation splitting
```

If `journal_scanner.py` raises for any reason, the handler falls through to a **second, lossier
regex parser** that returns `"annotations": []` for every entry. It still answers `200 {"ok": true}`.

The browser renders a journal that looks complete and has silently lost every annotation. Nothing —
not the response, not a log line — indicates degradation. `GET /data/journal` is *currently failing*
in the suite (`test-browser-data.bats:4`), so this fallback is not hypothetical.

**Fix direction:** the fallback parser should not exist. One parser, one grammar. If the scanner
fails, return `ok:false` with the error — a visibly broken journal is strictly better than an
invisibly incomplete one.

## 5. MEDIUM — the jrnl entry grammar has no contract

The entry header format `[YYYY-MM-DD HH:MM]` is parsed independently in:

- `lib/journal_scanner.py` (the canonical one, with annotation splitting)
- `services/browser/server.py` (the fallback regex — different semantics, drops annotations)
- `services/find/find.py`
- `services/community/community_store.py`

Four implementations, four opportunities to disagree, zero normative definition. Contrast the ledger
work, which produced `dev/schemas/ledgers-yaml-v1.md` — a versioned contract that makes "correct"
a checkable property.

**There is no `journals-yaml-v1` and no `journal-entry-v1`.** Until there is, "improve the journal
syntax" has nothing to be correct *against*, and every fix is a guess about what the other three
parsers assume.

This is the audit's central recommendation: **the contract is the deliverable.** The code fixes fall
out of it.

## 6. MEDIUM / LOW — duplication and standards drift

Byte-identical triplicates (md5 `78c1ca364d70b673236b134c9df9cc4c`):

```
services/questions/create-new-template-jrnl.sh
services/questions/templates/journal/create-new-template-jrnl.sh
services/scripts/journals/create-new-template-jrnl.sh
```

Byte-identical pair (md5 `c7dfb06fa2c29cbfc3f2f31a94a79f25`):

```
services/questions/jrnl-inquiryoverview-1.sh
services/questions/bin/jrnl-inquiryoverview-1.sh
```

Nobody knows which copy is live. Editing the wrong one is a silent no-op, and the next agent to
"fix" journal templates has a 1-in-3 chance of fixing a file nothing calls.

Standards violations (`dev/CLAUDE.md` calls these Gate B failures):

| File | Violation |
|---|---|
| `services/scripts/journals/create-new-template-jrnl.sh` | `#!/bin/bash`, not `#!/usr/bin/env bash` |
| `services/questions/handlers/journal_handler.sh` | `#!/bin/bash` |
| `services/questions/create-new-template-jrnl.sh` | `#!/bin/bash` |
| `services/questions/jrnl-inquiryoverview-1.sh` | `#!/bin/bash` |
| `services/custom/configure-journals.sh` | 120 raw `echo` for user-facing output; the contract mandates `lib/logging.sh` / `core-utils.sh` |

## 8. The test-index problem (surfaced by this audit)

`dev/tests/CLAUDE.md` carries a hand-maintained "Test File Index". Measured against reality:

| | Doc claims | Actual |
|---|---|---|
| Total | "~450 tests across 26 files" | 665 across 42 files |
| `test-profile-uda.bats` | 34 | 65 |
| `test-github-sync.bats` | 50 | 30 |

**13 files / 187 tests (28% of the suite) are absent from the index entirely** — including
`test-journal-annotation.bats` (19) and `test-journal-metadata.bats` (14).

`dev/CLAUDE.md` already names this failure mode: *"Never hand-maintain a mirror of a fact that lives
in 145 other files. It will drift."* The task board's cure was `wwctl index` (generated, `--check`
exits 1 when stale). The test index needs the same cure: `@covers:` / `@purpose:` tags declared in
each `.bats` file, a generated `dev/tests/INDEX.md`, and `select-tests.sh` rewritten as a query over
those tags rather than a hardcoded matrix.
